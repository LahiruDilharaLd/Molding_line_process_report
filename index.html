System Requirements & Development Process

1. Functional requirements

  • Digital form closely follows the photographed Molding Line Process Report.
  • Sequential time-slot entry for process measurements.
  • Immediate encrypted persistence after each report submission.
  • Search by date, time range, product and shift.
  • Select every slot for a selected date with one action.
  • Open a full record and its process readings at any time.
  • Print the selected results in an A4 report layout or choose “Save as PDF” from the browser print dialog.

2. Data integrity

  • Each saved report receives a unique record ID and creation timestamp.
  • Records are encrypted with AES-GCM using a key derived from the user's password with PBKDF2.
  • Storage uses IndexedDB, so the browser saves data locally rather than depending on a page refresh or temporary form state.

3. Important production note

This HTML/CSS/JavaScript-only version is a secure local prototype, not a multi-user enterprise database. Browser storage cannot provide server-grade security, central backup, audit trails, role-based access, or multi-device synchronization. For production deployment, use HTTPS plus an authenticated backend/database (for example, an API with PostgreSQL or another controlled database), server-side authorization, audit logging, automated backups and access controls.
